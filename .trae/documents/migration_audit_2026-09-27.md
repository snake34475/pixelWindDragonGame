# Unity 原型迁移综合评估

> 日期：2026-09-27
> 基线：`5d4ad31`（`feat: add 2D lighting`）
> 范围：`unity-app` 中已经存在的六个可玩机制，不含 Phase 9+ 新功能。

## 综合结论

Godot 版本已经完成 Unity 原型的**玩法链路迁移**，并建立了自动化测试、阶段文档和可重复资源生成流程。
当前主要差距不在代码状态机，而在以下两类：

1. 内容体量：旱魃地图目前只是最小可运行场景，没有还原完整地形。
2. 表现精度：部分视觉采用迁移期简化方案，包括 NPC 中文字体、水域遮罩和实际屏幕光照效果。

## 机制评分

| 机制 | 迁移状态 | 评价 |
| --- | --- | --- |
| 四向移动 + 双击奔跑 | 完成 | 输入、动画、Y-sort、相机和碰撞均有测试覆盖 |
| Q 石障破坏 | 完成 | 逻辑完整；碎石来源为 7 帧人工素材，原 Unity PSB 记录为 8 帧且无法可靠自动导出 |
| E + 左键钩爪 | 完成 | 信号解耦和状态机实现优于 Unity 原反向控制写法；视觉链未做摆动 |
| 传送圈 + 多场景 | 逻辑完成 | 双向切换和出生点可靠；旱魃地图内容未完整还原 |
| NPC 与对话框 | 逻辑完成 | 游荡、交互、锁定和自动关闭完整；默认字体与视觉排版仍需人工验收 |
| 池塘入水表现 | 逻辑完成 | 进出状态可靠；当前用蓝色半透明代替 Unity Sprite Mask 遮罩 |
| 2D 光照 | 基础完成 | 环境光、玩家、传送圈和火焰点光源已接入，未进行真实显示器亮度校准 |

## 工程质量

- 八组 SceneTree 无头测试覆盖全部迁移阶段，退出码可用于 CI。
- 地图、火焰序列帧和阶段资源均保留生成工具或可重复导入路径。
- 运行时逻辑通过信号、状态机和独立组件解耦，没有照搬 Unity 的反向 Transform 控制。
- `project.godot` 已声明 Godot 4.7，并在 4.7.2 下完成全量回归。

## 主要风险

| 风险 | 等级 | 说明 |
| --- | --- | --- |
| 完整旱魃地图缺失 | 高 | 影响后续新地图玩法的内容基础，但不影响当前传送逻辑 |
| 中文字体依赖默认字体 | 中 | 可能因平台字体回退产生显示差异，需要最终视觉验收 |
| 水域和锁链表现简化 | 中 | 当前偏功能验证，不等同原 Unity 的最终视觉效果 |
| README 与目录结构漂移 | 低 | 已有旧阶段占位，不影响运行，但会误导维护者 |

## 无风险改进

本轮先处理不会改变运行逻辑的项目：

1. 更新 README 的开发环境、目录结构、测试清单和 macOS 12 说明。
2. 修正 TODO 中 Phase 2 的测试数量。
3. 增加 `tools/run_tests.sh`，统一顺序运行八组测试。
4. 将本评估作为迁移基线文档保留，作为后续新功能设计的输入。

## 后续不宜自动推进的内容

- 完整旱魃地图还原：属于大体量内容转换，需要决定复用生成器还是单独制作。
- 中文字体与对话排版：需要真实渲染目视验收。
- 战斗、敌人、技能、装备、掉落等：Unity 原项目不存在，属于新功能设计。
